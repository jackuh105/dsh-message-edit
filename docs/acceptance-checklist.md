# 驗收清單:dsh-message-edit

> 對照:`docs/PRD.md`(29 條使用者故事)、`docs/message-edit.md`(四階段驗收條件)
> 前置:DSH 已重啟(`dsh --profile web`)、瀏覽器已重新整理、本對話已恢復。
> 執行方式:由使用者操作,代理逐項核銷並記錄結果。

## 0. 載入鏈路(Phase 1)

- [ ] `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3080/plugins/dsh-message-edit/client.js` → **200**
- [ ] `curl -s "http://127.0.0.1:3080/api/dsh-message-edit/state?sessionId=probe"` → **404** 且 body 為 `{"ok":false,"error":"unknown-session"}`(路由已掛載,僅 session 不存在)
- [ ] 頁面 console 無插件相關錯誤;原生功能(送出訊息、工具、設定)無退化
- [ ] `dsh --profile web --dump-config` 含 `# == dsh-message-edit` 層(已於安裝時驗證 ✓)

## 1. Undo(Phase 2;PRD 故事 9–18、21、22、25)

- [ ] 懸停任一自己送的訊息 → 出現 ↺(與 ✎);平時隱藏
- [ ] 點 ↺ → 該訊息**連同其後所有內容**立即消失,無確認框、無模型回應、輸入框未被預填
- [ ] 追問一個只有被移除內容才知道答案的問題 → 模型答不上來(上下文確實截斷)
- [ ] 對第一則訊息 ↺ → 全部清空,可重新開始
- [ ] agent 輸出中點 ↺ → 回合自動打斷,半截輸出不殘留(畫面與追問皆驗證)
- [ ] steering 訊息(回合中途插入)同樣可 ↺
- [ ] 含圖片/附件的訊息有 ↺、無 ✎
- [ ] 重新整理頁面 → 隱藏存活;重啟 DSH 後再開 → 隱藏存活;切換會話再切回 → 一致
- [ ] 已隱藏區間內不會再出現任何動作鈕

## 2. Edit(Phase 3;PRD 故事 1–8、19、20、24)

- [ ] 點 ✎ → 氣泡原地變文字框、預填原文、游標在尾;尾部訊息仍在畫面上
- [ ] Esc 或「取消」→ 還原氣泡,無任何痕跡
- [ ] 改字後按「傳送」→ 舊訊息及其後消失,新訊息出現在原位置並立即獲得回應
- [ ] 追問驗證:模型只記得編輯前的歷史 + 新訊息
- [ ] agent 輸出中按「傳送」→ 自動打斷,流程照常完成
- [ ] composer 有未送草稿時執行編輯送出 → 草稿原樣保留
- [ ] 在已 undo/編輯過的會話中,對更早的訊息再次操作 → 多區間累疊正確
- [ ] 編輯送出後立刻重新整理 → 新訊息與回應正常,擱置意圖不出現幽靈 ✕

## 3. 邊界與稽核(Phase 4;PRD 故事 27)

- [ ] 快速連點 ↺ / 傳送 → 無重複動作、無例外
- [ ] 編輯文字框開啟中切換會話再切回 → 狀態一致(文字框屬頁面狀態,消失可接受;不得殘留隱藏)
- [ ] JSONL 日誌:每次操作都有 `hook/invoked` + `source:'message-edit'` 記錄,phase 正確
- [ ] 卸載(`dsh plugin --profile web remove dsh-message-edit` + 重啟)→ GUI 恢復原生,日誌無害保留(驗收後如需保留插件則跳過此項)
